以下是根据**约定式提交（Conventional Commits）**规范整理的常用类型总结表格：

### 提交信息前缀（Type）用法总结表

| 前缀 (Type)    | 全称 / 含义           | 核心功能与使用场景                                           | 版本号影响 (SemVer)                      | 举例                             |
| :------------- | :-------------------- | :----------------------------------------------------------- | :--------------------------------------- | :------------------------------- |
| **`feat`**     | Feature（新功能）     | 新增了某个功能、特性、页面或接口。                           | **次版本号 +1** <br>*(如 1.1.0 → 1.2.0)* | `feat: 新增微信扫码登录`         |
| **`fix`**      | Bug Fix（修复缺陷）   | 修复了代码中的 Bug、报错或异常逻辑。                         | **修订号 +1** <br>*(如 1.1.0 → 1.1.1)*   | `fix: 修复金额计算精度丢失问题`  |
| **`merge`***   | Merge（合并）         | 自动生成（非人工手写），合并分支时 Git 自动产生的默认信息。  | 无直接影响                               | `Merge branch 'dev' into 'main'` |
| **`docs`**     | Documentation（文档） | 仅仅修改了文档，如 `README.md`、接口文档、代码注释等。       | 无影响                                   | `docs: 更新项目启动说明`         |
| **`style`**    | Styles（格式）        | 代码格式变动，**不影响代码逻辑**。如空格、缩进、分号、换行。 | 无影响                                   | `style: 格式化 utils 目录代码`   |
| **`refactor`** | Refactoring（重构）   | 代码重构，既没有加新功能，也没有修 Bug。如优化代码结构、提取公共方法。 | 无影响                                   | `refactor: 抽离表单校验公共逻辑` |
| **`perf`**     | Performance（性能）   | 优化代码性能，提升运行速度、减少内存占用等。                 | 无影响                                   | `perf: 优化首页大图加载速度`     |
| **`test`**     | Tests（测试）         | 添加缺失的测试用例，或修改现有的测试代码。                   | 无影响                                   | `test: 补充登录组件的单测`       |
| **`build`**    | Build（构建）         | 影响构建系统或外部依赖的更改。如升级 npm 包、修改 Webpack 配置。 | 无影响                                   | `build: 升级 vite 到 4.0`        |
| **`ci`**       | CI（持续集成）        | 修改 CI/CD 配置文件或脚本。如 GitHub Actions、GitLab CI 脚本。 | 无影响                                   | `ci: 增加自动化部署脚本`         |
| **`chore`**    | Chores（杂项）        | 其他不修改源码或测试的杂项变动。如修改 `.gitignore`、更新 `.eslintrc`。 | 无影响                                   | `chore: 忽略本地 vscode 配置`    |
| **`revert`**   | Revert（回退）        | 撤销之前的某个提交（通常由 `git revert` 自动生成）。         | 视情况而定                               | `revert: 撤销 feat: 微信登录`    |

---
**⚠️ 关于特殊后缀的补充：**
*   **`!` (破坏性变更)**：如果在类型后加 `!`（如 `feat!: 重构 API 返回格式`），表示这是一次**破坏性更新**（BREAKING CHANGE），原有功能将不兼容。
    *   *版本号影响*：**主版本号 +1**（如 1.1.0 → 2.0.0）。
*   **`scope` (作用域)**：括号里的内容，用来标明影响范围，如 `feat(login): ...`、`fix(api): ...`，非必填。
