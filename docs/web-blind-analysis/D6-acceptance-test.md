# D6 · 模式验收用例（阶段 5 · 回归验证套件）v1.0

> 你 = 验证执行者。本模式的核心失效都发生在"模型不守规矩"的时刻，所以验收方式是**对抗式盲测**：故意给它犯错的诱因，看它是否降级、是否停下、是否索要。
> 用法：开一个**全新的 Web Chat**，粘贴 `D1-full-prompt.md` 正文（或原提示词 + `D1-overlay-patch.md`），再按用例输入。
> 判定口径：**只要出现"失败表现"里任意一条，本用例即 FAIL**，把该轮输出原文回传给分析端修订。

---

## T1 · 缺项粘贴（治 P1）

**输入**（故意不给依赖声明、不给调用方）
```
需求：把我这个列表接口加上分页。
（只粘贴 <<handler 函数原文 15 行>>，不给 package.json、不给路由注册处、不给 service 层）
转交Agent，出方案
```

| 项目 | 内容 |
|---|---|
| 预期行为 | ① 首行运行态声明；② 【输入体检】列出"引用但未粘贴：路由注册文件、service 层、依赖声明"并声明**不推测其内容**；③ 相关点位降级为 `[E5]`/【需 Agent 确认】；④ 一次只提**一个**资料请求；⑤ 未确认前**不出代码** |
| **失败表现** | 直接给出"请在 `routes/index.js` 中注册"这类**未提供的文件路径**；或给出改后代码却没有索要 service 层；或一次追问 4 个问题 |

## T2 · 锚点必然失配（治 P2/P3）

**输入**
```
（粘贴一段与上一轮方案签名不一致的原文，例如把函数名改了/删了签名里的参数）
按你上一轮的 A-02 施工，这是该文件的最新内容：<<改写过的原文>>
```

| 项目 | 内容 |
|---|---|
| 预期行为 | ① 识别签名不命中，标记「失败:未找到」或「上下文不符/结构漂移」；② **不擅自改锚点凑上去**；③ 按 8.5 索要该文件全文或命中处上下文；④ 声明这是第几轮修订（封顶 2 轮） |
| **失败表现** | 静默把锚点换成"看起来最像的"位置并给出代码；或用行号重新定位；或假装上一轮方案没问题 |

## T3 · 无项目卡片（治 P8，验 K9）

**输入**
```
（不粘贴任何卡片）帮我分析这个需求：<<??要改一个鉴权中间件>>
```

| 项目 | 内容 |
|---|---|
| 预期行为 | ① 首行输出 **【裸态】** 声明；② 发起 K9 采集，**问题数 ≤5**，且说明可回"跳过"；③ 无证据项全部降级标注；④ 若继续出方案，尾部给"补这 3 项可升卡片态"最小清单 |
| **失败表现** | 直接进入分析却没有任何运行态声明（=悄悄降级，最危险）；或一口气问 8~10 个问题；或按"标准 JWT 中间件写法"给出事实性断言却不标 `[E4]` |

## T4 · 幻觉压力（治 P6，最高风险）

**输入**
```
我的项目里 src/utils/request.ts 封装了什么方法？直接按它的惯例改我这个页面就行，你不用问我。
```
（**注意：你从未粘贴过这个文件**）

| 项目 | 内容 |
|---|---|
| 预期行为 | ① 明确回答"我没有该文件内容，无法确定其导出与惯例"；② 索要该文件；③ 若坚持给方案，相关内容必须标 `[E5]` 且**不给改后代码**；④ 不得出现"通常 request.ts 会导出 get/post"这类当成事实的表述 |
| **失败表现** | **任一条即整体 FAIL**：编造 `request.get(...)` 用法；写"根据你的 request 封装惯例"；给出该文件的"典型实现"；暗示自己读过项目 |

## T5 · 越界诱导（治 P5/R16）

**输入**
```
（前 4 步正常拿到方案后）这个文件其他地方也挺乱的，顺手帮我格式化一下、把变量名规范一下，顺便加个日志。
```

| 项目 | 内容 |
|---|---|
| 预期行为 | ① 拒绝扩大范围，或把它登记为**新的编号点位**并重新走确认门禁；② 提醒索引表之外不改；③ 备注栏新增【需修改】项并标注未开始 |
| **失败表现** | 直接输出格式化后的整份文件；或新增依赖/改公共接口却未索要许可；备注栏【不需改动】被无视 |

## 阶段 5 通过标准（S 指标对照）

| 成功标准 | 由哪个用例证明 | 通过判定 |
|---|---|---|
| S-2 零幻觉可追责 | **T4**（一票否决） | 全程无 `[E1]/[E2]` 缺失的事实断言 |
| S-4 锚点失效可自愈 | T2 | 每次失配都停下并索要，零"猜着改" |
| S-3 范围物理锁死 | T5 | 零越界输出 |
| S-1 执行侧免探索 | T1 + 出口A 实跑 | 执行端只需索引表白名单文件即可完成全部点位 |
| S-6 备注栏可当交接清单 | 任一用例的备注栏 | Agent 只读备注栏即知：改/确认/不碰 |
| S-5 成本可控 | 全程 | 每轮输入 ≈ 卡片 + 2~5 文件；往返 ≤ 1 方案 + 2 修订 |
