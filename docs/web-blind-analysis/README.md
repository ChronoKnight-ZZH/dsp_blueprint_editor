# Web 盲分析 · 亮执行 模式 v1.0

零文件权限的 Web AI 做深度分析 → 产出可直接套用的分层修改方案 → 有权限的执行方零思考照单施工。
目标：把执行侧"读文件、重新推理、顺手重构"烧掉的 token 压到最低。

## 快速上手（3 步）

1. 开一个纯 Web Chat，粘贴 `D1-full-prompt.md` 的正文（或：原《顾问提示词》+ `D1-overlay-patch.md` 二选一）。
2. 填好 `D2-project-card.md` 并粘贴（不填则自动进入【裸态】并告警）。
3. 粘贴本次要改的文件原文 + 需求，按需要用触发词切换出口：
   - `转交Agent` → 出口A 方案，配 `D3-exec-agent-prompt.md` 交给本地/IDE Agent 执行
   - `人工执行` → 出口B 施工单，按 `D4-manual-worksheet.md` 结构逐点勾选施工

细则见 `D5-usage-guide.md`。

## 设计要点速查

- **证据码 E1~E5**：任何事实断言必须有来源；`[E4]`模型常识 / `[E5]`无来源 只能进【假设与风险】/【需 Agent 确认】，不得写成事实 → 治幻觉。
- **锚点 = 唯一签名串 + 前后上下文窗口，禁行号** → 治定位失效。
- **动作只允许 4 枚举：替换 / 新增 / 删除 / 插入** → 从措辞层锁死发挥空间。
- **停止契约 5 条 + 批量回传 6 字段 + 对账** → 失配即停不猜，一次收齐不挤牙膏。
- **执行侧定向读取白名单**：只准读索引表列出的文件来校验锚点，禁止搜索/列目录/重跑分析。
- **单一事实源**：出口A `A-xx` 与出口B `B-xx` 编号互认，两份由同一索引表派生，不得漂移。
- **备注栏即交接清单**：7 类固定，每轮 Δ + 阶段末全量，出口A 尾部附完整 7 类；执行端只认【需修改】编号。
