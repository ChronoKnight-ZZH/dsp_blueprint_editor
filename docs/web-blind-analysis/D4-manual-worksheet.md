# D4 · 人工施工单结构（E2 档正文骨架）v1.1

> 用法：v1.1 分层交付下，本结构是 **E2 档**——用户回复 `人工修改` / `给我代码` / `我自己改` / `出施工单` 时，分析端**由已交付的 E0 编号派生**（E0-xx → B-xx），逐点展开为人类步骤 + 该点源代码。
> **不允许跳过 E0 直接出 E2**，除非用户开局明确要求且原文证据充足（D1 §7.3）。
> 设计目的不变：治人工执行的三大错源——**贴漏、贴重、贴错顺序**（G4）。
> 编号升级链互认：`E0-01 ↔ A-01 ↔ B-01`，同一事实源派生（R1）。

## 粒度标注规则（分析端必须遵守，此处为对齐用）

| 条件 | 标注 | 依据 |
|---|---|---|
| 用户只粘贴了片段（哪怕 1 行） | **强制局部替换** + 声明原因 | K8 / N8，**不可被卡片或阈值覆盖** |
| 整文件粘贴，`≤150行` | 全量替换 | C-1 |
| 整文件粘贴，本文件改动点 `≥3 处` | 全量替换 | C-1 |
| 整文件粘贴，发生结构变化（新增 import、移动函数、调整块顺序） | 全量替换 | C-1 |
| 整文件粘贴，`>150行` 且 改动点 `≤2` | 局部替换 | C-1 |
| 全量输出会超过 400 行 | 强制局部替换 + 提示"如坚持全量请分块" | C-1 硬上限 |
