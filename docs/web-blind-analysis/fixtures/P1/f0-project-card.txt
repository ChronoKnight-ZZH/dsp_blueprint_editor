[4] 构建 / 测试 / lint 命令（真实可跑）
    安装：pnpm i
    开发：pnpm dev
    构建：pnpm build
    单元/集成测试：pnpm test            （vitest run）
    端到端：pnpm test:e2e              （需本地服务，默认跳过）
    静态检查：pnpm lint && pnpm typecheck
    格式化：pnpm format                （⚠ 见 [6]：禁止 AI 调用）
    期望成功标志：pnpm typecheck 退出码 0 且无 error 行；pnpm test 输出 "Test Files  N passed"

[5] 代码风格约定
    缩进 2 空格；双引号；必须加分号；尾逗号 all
    命名：文件 kebab-case（OrderList.tsx 为例外，React 组件文件用 PascalCase）；变量/函数 camelCase；类型 PascalCase；常量 SCREAMING_SNAKE
    导入顺序：三方库 → 绝对路径 @/ → 相对路径 → 类型 import type
    注释语言：中文
    错误处理：handler 内 try/catch → next(err)，禁止自行吞异常返回 500
    日志：禁止 console，统一 pino logger（本次任务未涉及日志改动）

[6] 禁改边界（★必填，越界拦截唯一依据）
    禁止修改文件：pnpm-lock.yaml、package.json（不得新增/升级依赖）、tsconfig*.json、vitest.config.ts
    禁止改动目录：src/routes/**、src/middleware/**、migrations/**、generated/**
    禁止行为：
      - 不得新增依赖（本项目无 axios；前端请求统一走 @/utils/request）
      - 不得修改已导出符号的名称（listOrdersHandler、fetchOrderList 等被外部引用）
      - 不得改变公共接口返回结构而不提出兼容性说明
      - 不得执行 pnpm format / 不得整体重排文件（项目 lint 未强制格式，格式化会产生大量无关 diff）
      - 不得修改测试快照
    需先问我才能动：数据库 schema、分页默认上限、导出文件大小阈值 5_000_000、鉴权与租户头逻辑
