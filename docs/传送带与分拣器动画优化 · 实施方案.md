# 传送带与分拣器动画优化 · 实施方案（v3 · 按实测修正）

> v3 变更摘要：新增「转角弧形」（90° 圆弧弯折，圆心 = 本格中心，`R = BELT_LEN/2`）与「上升/下降坡度」两项。两者都由**每实例属性 + 顶点着色器**完成，段长仍为一格、Draw Call 仍为 1；货物用同一组参数做**刚性跟随**。
>
> v2 变更摘要：修正 v1 的几何前提错误（传送带记录只有 1 格）、货物矩阵缩放顺序、孤立段方案改为圆点、条带颜色改用元数据色、箭头周期锁定为段长、删除 G9（GLSL 失败降级不可实现）。实测依据见附录 A。

## 1. 需求

将当前蓝图中传送带与分拣器的货物动画从「几何占位」升级为「可辨识的工业视觉」：

| #    | 需求原文                          | 拆解                                   |
| ---- | --------------------------------- | -------------------------------------- |
| R1   | 传送带从「点 + 线」改为长方形条带 | 有输出的格渲染为条带，每格一段、首尾相接 |
| R2   | 条带内置箭头流动                  | 条带顶面有沿流动方向滚动的箭头图案     |
| R3   | 上方是正方体货物                  | 货物几何改为立方体，浮在条带上方       |
| R4   | 货物和传送带颜色区分              | 条带取元数据色，货物取高亮度暖色       |
| R5   | 分拣器：横梁在上、货物在下        | 分拣器本体抬高，货物下移，两者垂直分离 |
| R6   | 分拣器货物颜色与分拣器区分        | 与 R4 同一套色彩语义                   |

> **R1 修订说明（实测约束）**：DSP 蓝图里每条传送带记录只代表 **1 格**，`localOffset[0] === localOffset[1]`（4 个 fixture、787 条带子，100% 成立，见附录 A）。因此「每段一条连续长条」只能落成「每格一段」；**没有输出对象的孤立带子无法确定方向，保留现有圆盘作为「圆点」**，见 G1。
>
> **转角与坡度也是逐格属性**：转角格的 `yaw` 是入/出方向的角平分线（切线是 `yaw ∓ 45°`），转弯量固定 90°；坡度来自相邻格 `localOffset.z` 的差值（一级台阶 `0.5 × 4/3 = 0.667` 世界单位，见 §3.4-F7/F8）。

## 3. 原理

### 3.1 现有架构的三个支点

本方案完全建立在现有架构之上，不引入新范式：

| 支点           | 位置                                      | 本方案如何复用                                       |
| -------------- | ----------------------------------------- | ---------------------------------------------------- |
| **实例化渲染** | `InstancedMesh`                           | 条带、圆点、横梁、货物各自一个 `InstancedMesh`，Draw Call 不随建筑数增长 |
| **每实例颜色** | `InstancedMesh.setColorAt`（`instanceColor`） | 条带取元数据色，与现有圆盘一致                       |
| **着色器注入** | `onBeforeCompile` + `MeshLambertMaterial` | 箭头在片元着色器里算，零 CPU 开销；复用 Lambert 光照 |

### 3.2 为什么箭头能「零 CPU 开销」

```
构建期：条带几何固定为「一格长」；每实例只写一组形状参数 aBeltCurve = (bend, slope)
渲染期：CPU 每帧只写一个 uniform：cargoMove ∈ [0, 1)
顶点期：vBeltPhase = position.z + 0.5      // 0..1，一段内归一化
片元期：fract(vBeltPhase + cargoMove)      // 相位向 -z（流动方向）滚动
```

关键点：

1. **周期 ≡ 段长**。段长恒为一格，`position.z + 0.5` 正好把「一段」归一化到 0..1，因此**不需要** `cargoDistance` 之类的「长度」每实例属性，也没有除法与精度问题（v1 的 S2、S6 随之删除）。`aBeltCurve` 只描述形状（弯折/坡度），不参与相位计算。
2. **相位符号必须是 `+ cargoMove`**。货物着色器做的是 `transformed.z -= cargoMove * d`（向 `-z` 走）；若箭头写成 `fract(phase - cargoMove)`，图案会向 `+z`（逆流向）滚动，与货物反向（v1 的错误）。
3. **跨格连续**。因为 `period = 段长`，每段恰好一个箭头周期，段与段之间没有 0.258 相位残留，箭头不会在格边界「跳一下」。

### 3.3 为什么横梁与货物能分离而不影响拾取

- 拾取盒由 `buildBVH` 的 `inserterTrans(transforms[i], box)` 生成，**只依赖 `inserterTrans`**；
- 本方案只在 `buildInserters` 内部对 `trans` 追加平移，**不修改 `inserterTrans` 的返回值语义**；
- 因此拾取盒位置不变，货物与横梁的视觉分离对拾取透明。

条带同理：带子的拾取盒来自 `buildingMeta.selectUnitBoxTrans × transforms[i][0]`，与条带网格无关。

### 3.4 数据事实与坐标系约定（不可违反）

**先列实测事实**（附录 A 有原始数据）：

| #    | 事实                                                                 | 影响                                                |
| ---- | -------------------------------------------------------------------- | --------------------------------------------------- |
| F1   | 每条传送带记录 = **1 格**，`localOffset[0] === localOffset[1]`（误差 0） | **禁止**用 `tr[0]`→`tr[1]` 求段长（v1 的致命错误）  |
| F2   | 一格的世界长度 = `GRID_HORIZONTAL = 2π/200/5 × 200.2 ≈ 1.2578`         | 条带长度取该常量；经纬两个方向同尺度                |
| F3   | 建筑基准面就是球面（`SphereGeometry(PLANET_RADIUS)`，`PLANET_RADIUS = 200.2`） | 条带中心必须抬升 `BELT_HEIGHT/2` 才不半埋           |
| F4   | 带子 `yaw[0] === yaw[1]`（实测 100%，每格是直段）                     | 方向只需 `yaw[0]`；转角由相邻格的 yaw 差异体现      |
| F5   | yaw → 格子方向：`0→(0,+1)`、`90→(+1,0)`、`180→(0,-1)`、`270→(-1,0)`，即 `dir = (sin yaw, cos yaw)` | 孤立段判定/未来方向推导的依据（本次孤立段用圆点，不依赖它） |
| F6   | 带子颜色来自 `buildingMeta`：2001 `0xe3a263`（橙）、2002 `0x51a896`（青）、2003 `0x61a5d7`（蓝） | 货物色不能接近橙色，否则 R4 不达标                  |
| F7   | **转角格的 `yaw` 是入/出方向的角平分线**：实测 `yaw=224.99` 而出格方向 `270`、`yaw=137.29` 而出格 `180`、`yaw=135.37` 而出格 `90` | 转角切线 = `yaw ∓ 45°`，转弯量恒为 90°；直段仍用 `yaw` |
| F8   | 坡度 = 相邻格 `localOffset.z` 差：`0.5`（一级台阶）→ `0.5 × HEIGHT_GRID_SIZE(4/3) = 0.667` 世界单位，折合约 28° | 条带需按 Δz 倾斜；高度层为 `0 / 0.5 / 1.0` 三档         |
| F9   | 存在 `Δz = ±0.01/0.02` 的亚台阶值（区域拼接/浮点）                     | 需阈值过滤，`abs(Δz) < BELT_SLOPE_EPS` 视为平地      |
| F10  | 位移方向全部轴对齐（0/90/180/270），没有 45° 对角移动                   | 95% 以上的带子是直段，转角仅占 1%~5%                  |

**坐标系约定**：

| 约定     | 值                          | 来源                                                        |
| -------- | --------------------------- | ----------------------------------------------------------- |
| 流动方向 | 条带局部 `-z`               | `cargos.ts` 的 `transformed.z -= cargoMove * cargoDistance` |
| 直段定向 | `base × Rx(π/2)`           | `base`（`calcBuildingTrans` 的 `Ry(lon)·Rx(-lat)·Rz(-yaw)`）**已含 yaw**；再乘一次 `Rz(-yaw)` 会变成 `-2·yaw`（实测同向率 0%，见附录 A）。`Rx(π/2)` 把「建筑局部 +y＝流向」映射到「条带 -z」 |
| 转角定向 | 同上，**不做额外旋转**     | F7：`base` 的局部 -z 就是角平分线，相邻边中点落在 45° 方向，着色器据此弯 90° 即可两端对齐（§3.6） |
| 弯折量   | `bend ∈ {0, ±π/2}`           | 由「出格方向相对 yaw 的左右」决定符号（§3.6）                |
| 坡度量   | `slope = (z_out - z_self) × HEIGHT_GRID_SIZE` | F8；本格后缘 = `z_self`，前缘 = `z_out`，故实例再抬 `slope/2` |
| 条带宽度 | 局部 `x`（0.95）            | 一格 1.2578，留 0.31 间隙                                   |
| 抬升方向 | 局部 `y`（法线）            | `Rx(π/2)` 后局部 +y = 建筑局部 +z = 球面法线                |
| 段长     | `BELT_LEN = GRID_HORIZONTAL` | F2                                                          |

> 派生：条带矩阵 `base × Rx(π/2) × T(0, BELT_LIFT + slope/2, 0)`（**无缩放**，长度已烘进几何），盒体以原点为中心 → 恰好覆盖本格 `±BELT_LEN/2`，相邻格首尾相接。

### 3.5 为什么删掉 G9

- Three.js 的 GLSL 编译失败由 WebGL 驱动侧报告，`onBeforeCompile` 与 `render()` 都不会抛出可捕获的 JS 异常；表现是 console 报错 + 该材质黑屏/不渲染，没有「降级为纯色条带」的钩子。
- 唯一可做的「降级」是提前把 `onBeforeCompile` 换成空实现再重建材质，这属于事后补救，且需要重新编译整批材质，代价与收益不成比例。
- Jest 无 WebGL，无法把「写错 GLSL」纳入 CI。
- **替代措施**：着色器保持极小（≤ 20 行注入）、只注入两个 chunk、人工冒烟验收（§9.3-E-5）；如需线上排障开关，可在后续版本加 URL 参数关闭注入（非本次范围）。

### 3.6 转弯弧形与坡度的几何推导

**前提**：转角格的 `yaw` 是入/出方向的角平分线（F7）。`base` 已内含 `Rz(-yaw)`，所以条带局部 `-z`（流向）**正好是角平分线**。此时相邻两条格边的中点在局部坐标里落在 `(±L/(2√2), ±L/(2√2))`（L = 1.2578 → 0.445），即 45° 方向上。

**弯折（90° 转角）**

| 项目     | 值 / 做法 |
| -------- | --------- |
| 输入     | 每实例 `bend ∈ {0, ±π/2}`（0 = 直段） |
| 圆弧     | **圆心 = 本格中心**，半径 `R = BELT_LEN / 2 = 0.629`，张角 90°，从入射边中点扫到出射边中点 |
| 参数化   | `u = position.z / BELT_LEN + 0.5`（0 = 后缘/入射，1 = 前缘/出射）；`θ = π/4 + bend·u`；`P = (R + position.x)·(sin θ, 0, cos θ)`，`y` 不变 |
| 端点     | `u=0 → (0.445, 0, 0.445)`、`u=1 → (0.445, 0, -0.445)`：正是两条相邻格边的中点 → **与相邻直段无缝、且切线连续** |
| 弧长     | `R·π/2 = 0.988`，是 `BELT_LEN` 的 **78.6%** |
| 箭头     | 相位仍按 `u` 线性映射（段内恰好一个完整周期），**跨格相位连续**；但转角段弧长只有 78.6%，图案沿弧长被压缩到 78.6%——这是「两端必须落在格边中点」的几何必然，不是缺陷（B-4 按此判定） |
| 自交     | 内圈 `R - BELT_WIDTH/2 = 0.629 - 0.475 = 0.154 > 0`，不自交；但余量很紧，`BELT_WIDTH` 一旦超过 `BELT_LEN` 就会翻面 |
| 左/右转  | `bend` 符号由「出格方向相对 yaw 的左右」决定；实现后用 1 个 fixture 的转角格校核，必要时整体取反 |
| 直段保护 | `abs(bend) < 1e-4` 时整段跳过弯折（否则 `θ` 为常数，整条带子被压成一个点） |

> **不能用「等弧长 R = L/|bend| = 0.8」**：那样弧长虽然等于 L（箭头完全不变形），但端点会落到 `(0.8, ±0.171)`，与相邻格的边中点差 0.24，转角外侧出现可见的错台/缺口。几何连续 + 切线连续优先于箭头等长。

**坡度**

- 高度是逐格离散值：`h_i = z_i × HEIGHT_GRID_SIZE(4/3)`，档位 `0 / 0.5 / 1.0`。
- 为让相邻条带高度连续，约定：**本格后缘取 `h_i`，前缘取 `h_{i+1}`**，因此：
  - 实例位置沿法线再抬 `slope / 2`（`slope = h_{i+1} − h_i`）；
  - 顶点着色器做纵向剪切 `transformed.y -= (position.z / BELT_LEN) × slope`（后缘 `+L/2` → `−slope/2`，前缘 `−L/2` → `+slope/2`）。
- 用**剪切**而不是旋转：横截面保持竖直、厚度不变，28° 下与真实旋转的差异不可见，还能省掉一次法线变换。
- 箭头不受影响（图案在顶面，随顶面一起倾斜）。
- **不适用场景**：输出不是带子、输出距离不是 1 格、或无输出 → `slope = 0, bend = 0`（避免机器 3×3 中心造成假方向、分流器侧口造成假坡度）。

**必须同步的几何改动**：弯折要在**真实世界单位**下计算。现有实现是「单位长盒子 + 实例 `scale(1,1,BELT_LEN)`」，非等比缩放会把圆弧压成**椭圆**（x 不变、z 拉长 1.26 倍），端点也就对不上邻格。因此条带几何改为 `BoxGeometry(BELT_WIDTH, BELT_HEIGHT, BELT_LEN)`，**实例矩阵不再做 z 缩放**（构建期少乘一次 `makeScale`）。圆点不受影响。

**组合（转角 + 坡度）**：两者在同一局部坐标系里，统一按「**先坡度剪切、后弯折**」执行（剪切只改 `y`，弯折只在 `x-z` 平面内，顺序可交换）；结果是「带坡度的 90° 圆弧」。

**货物**

| 维度 | 做法 |
| ---- | ---- |
| 坡度 | `transformed.y -= (transformed.z / BELT_LEN) × slope`（`transformed.z` 已含滑动位移，自动成立） |
| 弯折 | **不能逐顶点弯折**：0.3 的立方体在 `R=0.629` 上跨 27°，逐顶点会把立方体扭歪。改用 `u = 0.5 − cargoMove` 求**中心**角 `θc = π/4 + bend·(1 − cargoMove)`，整块平移 `R·(sin θc, 0, cos θc)` 并绕 y 旋转 `(θc − π/2)` |
| 直段 | `abs(bend) < 1e-4` 时退化为现有 `transformed.z -= cargoMove · cargoDistance` |

## 5. 工作流程

### 5.1 文字流程

**用户视角**：导入蓝图 → 3D 场景出现条带传送带与分拣器 → 条带顶面箭头滚动、货物沿条带/横梁下方滑动 → 点选建筑 → 编辑 → 场景重建。

**构建期**（`buildBuildings`，一次性）：

1. 分类 belts / inserters / boxes；
2. `buildBelts`：
   - 先建 `Map<BlueprintBuilding, index>`，逐格求形状参数 `(bend, slope)`（§3.6）。只有「输出是带子 **且** 输出格与本格相差 1 格」才计算，否则 `bend = slope = 0`：
     - `slope = (z_out − z_self) × HEIGHT_GRID_SIZE`；`|Δz| < BELT_SLOPE_EPS` 归零（F9）；
     - `bend`：转角格出格方向与 `yaw` 差 ±45°（F7），按符号取 `±π/2`，直段为 0；
   - 拆两组：`withOutput`（`outputObjIdx >= 0`）画条带，`isolated`（`outputObjIdx < 0`）画圆点；
   - 条带：`base × Rx(π/2) × T(0, BELT_LIFT + slope/2, 0)`（**无缩放**，`BELT_LEN` 已烘进几何），颜色 `colorOf(modelIndex)`，形状写 `setCurveAt(i, bend, slope)`；
   - 货物：同姿态但**不缩放**，`T(0, CARGO_LIFT, BELT_LEN/2)` 退到本格后缘，再 `addCargo(cargoTrans, color, len, bend, slope)`；
   - 圆点：沿用现有 `CylinderGeometry(0.32,0.32,0.1,8)` + `translate(0,0,0.05) × rotateX(π/2)`；
   - `modelRef[b.index] = { matrix: base }`（保持 `getBuildingModel` 旧语义）；
3. `buildInserters`：`inserterTrans` 取基础姿态 → 先 `copy` 给货物并下移 → 再对 `trans` 追加抬高与缩放 → 分别写两个 `InstancedMesh`；
4. 收尾：`instanceMatrix.needsUpdate` / `instanceColor.needsUpdate`；
5. 组装 `AllBuildings`，返回 `stats`。

**渲染期**（每帧）：

1. `cargoMove = (time % 1000) / 1000`；
2. 同时赋给 `cargos.cargoMove` 与 `belts.cargoMove`（`belts` 为 `null` 时判空）；
3. GPU 完成位移与箭头滚动。

### 5.2 阶段表

| 阶段      | 触发                                          | 输入                                  | 动作               | 输出                          | 失败路径                                        |
| --------- | --------------------------------------------- | ------------------------------------- | ------------------ | ----------------------------- | ----------------------------------------------- |
| S1 构建   | `execVersion++` / `modelVersion++` / 首次加载 | `transforms`、`buildings`、`settings` | `buildBuildings()` | `AllBuildings` + `BuildStats` | 抛错 → `RenderPhaseError("build")` → 保留旧场景 |
| S2 挂载   | `watchEffect`                                 | 新 `AllBuildings`                     | `scene.add()`      | 场景更新                      | 无（同步）                                      |
| S3 帧更新 | rAF                                           | `time`                                | 写 `cargoMove`     | uniform 更新                  | 无                                              |
| S4 GPU    | 渲染                                          | uniform                               | 顶点/片元着色      | 像素                          | shader 编译失败 → console 报错，见 §3.5         |
| S5 回收   | 重建 / `dispose`                              | 旧 `AllBuildings`                     | `dispose()`        | 几何显存释放                  | 无（幂等）                                      |

### 5.3 失败路径与原子性

| 场景                                    | 行为                                                         | 原子性                                |
| --------------------------------------- | ------------------------------------------------------------ | ------------------------------------- |
| `buildBuildings` 抛错                   | `RenderCore.rebuildScene` 捕获 → `RenderPhaseError("build")` → **旧 bundle 保留** | 先构建后替换，天然原子                |
| 条带 `onBeforeCompile` 注入的 GLSL 非法 | 浏览器报 shader 编译错误 → 条带黑屏；**开发期人工冒烟必须覆盖**；无降级（§3.5） | —                                     |
| 输出格不是带子 / 距离不是 1 格 / 无输出 | `bend = slope = 0`，退化为直段平地（不猜方向、不猜坡度） | 安全 |
| 输出格 `Δz` 为亚台阶（±0.01/0.02）      | `abs(Δz) < BELT_SLOPE_EPS` 归零，不产生可见倾斜（§3.4-F9）   | 安全 |
| 直段 `bend = 0` 时着色器 `R = BELT_LEN/abs(bend)` | 用 `max(abs(bend), 1e-4)` + `step` 分支跳过弯折，避免除零产生 NaN | NaN 会让整条带子消失 |
| 孤立段（`outputObjIdx < 0`）            | 画圆点，不画条带、不产生货物                                 | 安全                                  |
| `belts.length === 0`                    | `belts` 为 `null`，渲染循环判空                              | 安全                                  |
| 全部带子都是孤立段                      | 只有圆点 mesh，`belts` 为 `null`                             | 安全                                  |
| 重建时旧 `AllBuildings.dispose()`       | 释放条带/圆点/货物的几何（`traverse` 已覆盖）；材质维持现状不释放 | 见 §6.6-S7                            |

**回滚策略**：纯代码改动，无数据迁移、无存储结构变更。回滚 = `git revert` 到改动前 commit，无需清理用户本地状态（`sessionStorage` 的 `renderSettings` 不含本方案字段）。

### 6.2 接口设计

```ts
// src/belt.ts（新增）
import { GRID_HORIZONTAL } from "@/planetConstants";

/** 条带几何尺寸（世界单位） */
export const BELT_WIDTH = 0.95;
export const BELT_HEIGHT = 0.08;
/** 条带中心抬升：底面贴球面（§3.4-F3） */
export const BELT_LIFT = BELT_HEIGHT / 2;
/** 段长 = 一格（§3.4-F2） */
export const BELT_LEN = GRID_HORIZONTAL;
/** 坡度阈值：abs(Δz) 小于该值视为平地，过滤 ±0.01/0.02 亚台阶（§3.4-F9） */
export const BELT_SLOPE_EPS = 1e-3;
/** 直段保护：abs(bend) 小于该值时跳过弯折，避免 θ 退化成常数（§3.6） */
export const BELT_BEND_EPS = 1e-4;
/** 箭头颜色可调；条带颜色不使用常量，取 buildingMeta（§3.4-F6 / G5） */
export const BELT_ARROW_COLOR = new Color(0x9aa0a6);

class BeltMaterial extends MeshLambertMaterial {
    readonly cargoMoveUniform: { value: number };   // 0..1 相位
    readonly arrowColorUniform: { value: Color };
    onBeforeCompile(p: WebGLProgramParametersWithUniforms): void;
    customProgramCacheKey(): string;                // "dsp-belt-arrow-v2"（注入改了必须升版）
}

export class Belts extends InstancedMesh {
    declare geometry: BoxGeometry;                  // 必须 declare（useDefineForClassFields）
    declare material: BeltMaterial;
    constructor(count: number);                     // BoxGeometry(W, H, BELT_LEN)：长度烘进几何，实例不再缩放
    /** 写第 i 个实例的形状参数（构建期一次性调用）；不调用则默认 (0, 0) = 直段平地 */
    public setCurveAt(i: number, bend: number, slope: number): void;
    public get cargoMove(): number;
    public set cargoMove(v: number);
}
```

> 条带长度必须烘进几何（`BoxGeometry(..., BELT_LEN)`），**不能再靠实例 `scale(1,1,BELT_LEN)`**：非等比实例缩放会作用在顶点着色器的输出上，把圆弧压成椭圆（§3.6）。

### 6.3 方法：`buildBelts` 重写骨架

```ts
const buildBelts = (belts: BlueprintBuilding[]) => {
    const objects: Object3D[] = [];

    // ── ⓪ 形状参数：只对「输出是带子且正好一格」的格计算（§3.6） ──
    const byIndex = new Map(buildings.map((b) => [b.index, b]));
    const shapeOf = (b: BlueprintBuilding) => {
        const out = byIndex.get(b.outputObjIdx);
        if (!out || !isBelt(out.itemId)) return { bend: 0, slope: 0 };

        const o = b.localOffset[0], p = out.localOffset[0];
        const dx = p.x - o.x, dy = p.y - o.y;
        const oneGrid =
            (Math.abs(Math.abs(dx) - 1) < 1e-3 && Math.abs(dy) < 1e-3) ||
            (Math.abs(Math.abs(dy) - 1) < 1e-3 && Math.abs(dx) < 1e-3);
        if (!oneGrid) return { bend: 0, slope: 0 };   // 侧口 0.2 / 隔格 2.4 → 不猜

        const raw = (p.z - o.z) * HEIGHT_GRID_SIZE;   // 世界单位
        const slope = Math.abs(raw) < BELT_SLOPE_EPS ? 0 : raw;

        // 自身 yaw 是角平分线（F7）：出格方向与之差 ±45° → 左右转，差 0 → 直段
        const yaw = (b.yaw[0] / 180) * Math.PI;
        const turn = Math.atan2(
            Math.sin(yaw) * dy - Math.cos(yaw) * dx,
            Math.sin(yaw) * dx + Math.cos(yaw) * dy
        );
        const bend = Math.abs(turn) > 0.1 ? Math.sign(turn) * (Math.PI / 2) : 0;
        return { bend, slope };
    };

    // ── ① 条带：只给有输出的格（每格一段） ──
    const withOutput = belts.filter((b) => b.outputObjIdx >= 0);
    let beltMesh: Belts | null = null;
    if (withOutput.length) {
        beltMesh = new Belts(withOutput.length);
        // base 已含 yaw，只需 Rx(π/2) 把「建筑 +y＝流向」映射到「条带 -z」
        const rot = new Matrix4().makeRotationX(Math.PI / 2);
        const trans = new Matrix4();
        const cargoTrans = new Matrix4();
        const temp = new Matrix4();

        for (let i = 0; i < withOutput.length; i++) {
            const b = withOutput[i];
            const base = transforms[b.index][0];
            const { bend, slope } = shapeOf(b);

            // 无 scale：BELT_LEN 已烘进几何（否则圆弧会被压成椭圆，§3.6）
            trans.copy(base).multiply(rot);
            trans.multiply(temp.makeTranslation(0, BELT_LIFT + slope / 2, 0));

            beltMesh.setMatrixAt(i, trans);
            beltMesh.setColorAt(i, colorOf(b.modelIndex));  // 元数据色（G5 硬要求）
            beltMesh.setCurveAt(i, bend, slope);            // 顶点着色器据此弯折/剪切
            modelRef[b.index] = { matrix: base };           // 保持 getBuildingModel 旧语义

            // 货物：同姿态、**先 copy 再动手**、不缩放、退到本格后缘（+z 为逆流向）
            cargoTrans.copy(base).multiply(rot);
            cargoTrans.multiply(
                temp.makeTranslation(0, CARGO_LIFT + slope / 2, BELT_LEN / 2)
            );
            addCargo(cargoTrans, CARGO_COLOR, BELT_LEN, bend, slope);
        }
        beltMesh.instanceMatrix.needsUpdate = true;
        if (beltMesh.instanceColor !== null)
            beltMesh.instanceColor.needsUpdate = true;
        objects.push(beltMesh);
    }

    // ── ② 孤立段：圆点（沿用现有圆盘，P0-3） ──
    const isolated = belts.filter((b) => b.outputObjIdx < 0);
    if (isolated.length) {
        const geometry = new CylinderGeometry(0.32, 0.32, 0.1, 8);
        const material = new MeshLambertMaterial();
        const dots = new InstancedMesh(geometry, material, isolated.length);
        const offset = new Matrix4().makeTranslation(0, 0, 0.05);
        offset.premultiply(new Matrix4().makeRotationX(Math.PI / 2));
        const trans = new Matrix4();
        for (let i = 0; i < isolated.length; i++) {
            const b = isolated[i];
            trans.copy(transforms[b.index][0]).multiply(offset);
            dots.setMatrixAt(i, trans);
            dots.setColorAt(i, colorOf(b.modelIndex));
            modelRef[b.index] = { matrix: transforms[b.index][0] };
        }
        dots.instanceMatrix.needsUpdate = true;
        dots.instanceColor!.needsUpdate = true;
        objects.push(dots);
    }

    return { objects, beltMesh };
};
```

**关键点（逐条对应修正项）**：

- **不再读 `transforms[b.index][1]`**（段长恒 0，P0-1）；方向与长度都来自 `yaw[0]` 与 `GRID_HORIZONTAL`，因此相邻格天然首尾相接，且不依赖 `outputObjIdx` 指向谁（转角/分流器侧口都不会画出斜条）。
- **货物矩阵 `copy(base)` 后立即 `multiply(rot)`，全程不碰 `scale`**（P0-2）；抬升与后缘偏移都在未缩放矩阵上完成，位移量正好等于段长。
- **孤立段一律圆点**（P0-3），不产生货物、不产生条带。
- **`modelRef` 必须写**，且只能用 `base`（无 scale、无 `len/2` 平移）；指向条带 mesh 会让 `getBuildingModel` 返回被拉伸的矩阵。
- `withOutput.length === 0` → `beltMesh` 为 `null`，`AllBuildings.belts` 为 `null`，帧循环判空。

### 6.4 方法：`buildInserters` 重写骨架

```ts
const buildInserters = (inserters: BlueprintBuilding[]) => {
    const INSERTER_THICKNESS = 0.06;
    const BEAM_EXTRA_LIFT = 0.1;                        // 横梁再抬高
    const CARGO_DROP = 0.1;                             // 货物下移

    const geometry = new BoxGeometry(0.15, INSERTER_THICKNESS, 1.0);
    const material = new MeshLambertMaterial();
    const mesh = new InstancedMesh(geometry, material, inserters.length);
    const offset = new Matrix4().makeTranslation(0, 0, -0.5);
    const temp = new Matrix4(), trans = new Matrix4(), cargoTrans = new Matrix4();

    for (let i = 0; i < inserters.length; i++) {
        const b = inserters[i];
        const len = inserterTrans(transforms[b.index], trans);   // 不改 inserterTrans

        // ① 货物：基础姿态下移（必须在 trans 被 multiply 前 copy）
        cargoTrans.copy(trans).multiply(temp.makeTranslation(0, -CARGO_DROP, 0));
        addCargo(cargoTrans, CARGO_COLOR, len);

        // ② 横梁：基础姿态抬高 + 缩放
        trans.multiply(temp.makeTranslation(0, BEAM_EXTRA_LIFT, 0));
        trans.multiply(temp.makeScale(1, 1, len));
        trans.multiply(offset);

        mesh.setMatrixAt(i, trans);
        mesh.setColorAt(i, colorOf(b.modelIndex));      // 横梁保持元数据色
        modelRef[b.index] = { mesh, instance: i };
    }
    mesh.instanceMatrix.needsUpdate = true;
    mesh.instanceColor!.needsUpdate = true;
    return [mesh];
};
```

**垂直预算（复核）**：

| 部件 | y 范围       | 计算                                |
| ---- | ------------ | ----------------------------------- |
| 横梁 | [0.37, 0.43] | `INSERTER_HEIGHT(0.3) + 0.1 ± 0.03` |
| 货物 | [0.05, 0.35] | `INSERTER_HEIGHT(0.3) - 0.1 ± 0.15` |
| 间隙 | **0.02**     | `0.37 - 0.35`                       |

> 注：`modelRef` 仍指向横梁 mesh，其矩阵随横梁上移 0.1，`SpitterInfo` 的投影位置同步偏移 0.1（视觉一致，不影响拾取）。

### 6.5 着色器注入（唯一有编译风险的环节）

**顶点着色器**（`meshlambert_vert`）：

```glsl
// 插到 #include <common> 之前
attribute vec2 aBeltCurve;  // x = bend（0 或 ±π/2），y = slope（世界单位）
uniform float cargoMove;
varying float vBeltPhase;   // 0..1，一段内归一化（因 period ≡ 段长）
varying float vBeltX;       // 条带宽度方向，-BELT_WIDTH/2 .. +BELT_WIDTH/2
varying float vBeltNY;      // 实例局部法线 y，用于顶面判别

// 插到 #include <begin_vertex> 之后
float bend  = aBeltCurve.x;
float slope = aBeltCurve.y;

vBeltPhase = position.z / BELT_LEN + 0.5;   // BELT_LEN 由模板字符串插值写入
vBeltX = position.x;
vBeltNY = normal.y;

// ① 坡度：纵向剪切（改 y，不影响弯折）
transformed.y -= (position.z / BELT_LEN) * slope;

// ② 弯折：绕本格中心、半径 BELT_LEN/2 的 90° 圆弧（§3.6）
if (abs(bend) > BELT_BEND_EPS) {
    float th = PI * 0.25 + bend * vBeltPhase;
    float r  = BELT_LEN * 0.5 + position.x;   // 用原始 position.x，不能用已改的 transformed
    transformed.x = r * sin(th);
    transformed.z = r * cos(th);
}
```

**片元着色器**（`meshlambert_frag`）：

```glsl
// 插到 #include <common> 之前（fragment 也必须声明 uniform 与 varying）
uniform float cargoMove;
uniform vec3 uArrowColor;
varying float vBeltPhase;
varying float vBeltX;
varying float vBeltNY;

// 插到 #include <normal_fragment_begin> 之后（此时 normal 已可用，diffuseColor 仍可改）
float topMask  = step(0.5, vBeltNY);                 // 只画顶面
float phase    = fract(vBeltPhase + cargoMove);      // + 号：向 -z（流动方向）滚动
float across   = abs(vBeltX) / (0.95 * 0.5);         // 0 = 中线，1 = 边缘
float slant    = 0.10 + across * 0.26;               // 斜边：越靠边越靠后 → 人字箭头
float band     = smoothstep(0.055, 0.0, abs(phase - slant));
float edgeFade = smoothstep(0.60, 0.38, across);     // 只保留中间约 76% 宽度
float mask     = topMask * band * edgeFade;
diffuseColor.rgb = mix(diffuseColor.rgb, uArrowColor, mask * 0.9);
```

**实现约束（对应用户确认项）**：

| #    | 约束                                                                     | 违反后果                                   |
| ---- | ------------------------------------------------------------------------ | ------------------------------------------ |
| GL1  | 不用 `uv`/`vUv`：Lambert 无贴图时 `USE_UV` 未定义，**必须**从 `position` 算  | 引用 `uv` 编译失败                         |
| GL2  | 必须有宽度方向坐标（`position.x`），只用长度坐标只能画横条纹，画不出箭头 | 视觉不满足 R2                              |
| GL3  | 必须有法线 mask（`normal.y`），否则六个面都是箭头                        | 视觉错误                                   |
| GL4  | `cargoMove` / varying 必须在 **fragment 也声明**                          | 编译失败                                   |
| GL5  | 注入点选 `#include <normal_fragment_begin>` 之后，且不要动 `normal` 本身   | 光照异常或 `normal` 未定义                 |
| GL6  | `customProgramCacheKey()` 返回 `"dsp-belt-arrow-v2"`（注入改了必须升版），且与 `CargoMaterial` 不同 | Three.js 复用错 program，uniform 串味 |
| GL7  | 箭头颜色走 `uArrowColor` uniform，并在 `#include <color_fragment>` **之后**覆写 | 若走 `instanceColor` 相乘，箭头会被带子色染暗 |
| GL8  | GLSL 里的 `0.95`（条带宽度）必须由 `BELT_WIDTH` 模板字符串插值写入，不能手写两份 | 调宽时只改一处，避免「条带 0.95 / 箭头按 1.0 算」错位 |
| GL9  | `bend` / `slope` 必须走 **instanced attribute**（`aBeltCurve` / `aCargoCurve`），不能用 uniform | 逐实例值不同，uniform 只能描述整批 |
| GL10 | 弯折必须在**真实单位**下算：几何长度烘成 `BELT_LEN`，实例不再缩放 | 非等比缩放把圆弧压成椭圆，端点对不上邻格 |
| GL11 | 直段必须用 `if (abs(bend) > BELT_BEND_EPS)` 跳过，不能靠 `atan` 之类「极限趋近」 | `bend=0` 时 `θ` 为常数，整条带子被压成一个点 |
| GL12 | 货物只做「中心沿弧 + 整体旋转」，不逐顶点弯折 | 立方体跨 27° 会被扭歪 |
| GL13 | `PI` 直接用即可（three 的 `<common>` 已 `#define PI`），不要在注入片段里重复 `#define` | 重复定义触发编译警告/失败 |
| GL14 | 弯折只改 `transformed.x/z`，**不动 `normal`**：顶面法线仍为 +y，箭头 mask 不受影响 | 若要改侧面法线需额外旋转，本次不做（侧面仅 0.08 厚） |

> 条带颜色走 `setColorAt(colorOf(modelIndex))`（G5）；箭头在 `color_fragment` 之后 `mix` 覆写，因此箭头色不受元数据色影响，只受光照影响。

**货物顶点着色器**（`CargoMaterial`，与条带同一套参数）：

```glsl
// 插到 #include <common> 之前
attribute vec2 aCargoCurve;   // x = bend, y = slope

// 插到 #include <skinning_vertex> 之后（替换现有的一行滑动）
float bend  = aCargoCurve.x;
float slope = aCargoCurve.y;
float zc    = BELT_LEN * (0.5 - cargoMove);   // 货物中心在本格内的 z（+ 后缘，- 前缘）
transformed.z -= cargoMove * cargoDistance;   // 沿用现有滑动
transformed.y -= (transformed.z / BELT_LEN) * slope;   // 坡度：绕自身中心倾斜

if (abs(bend) > BELT_BEND_EPS) {
    float th = PI * 0.25 + bend * (1.0 - cargoMove);
    float ca = cos(th - PI * 0.5), sa = sin(th - PI * 0.5);
    float lx = transformed.x, lz = transformed.z;      // 相对立方体中心的偏移
    transformed.x = BELT_LEN * 0.5 * sin(th) + lx * ca + lz * sa;
    transformed.z = BELT_LEN * 0.5 * cos(th) - lx * sa + lz * ca - zc;
}
```

### 6.6 安全要点

| #    | 要点                                                                 | 后果 if 违反                                       |
| ---- | -------------------------------------------------------------------- | -------------------------------------------------- |
| S1   | **禁止用 `transforms[i][1]` 求带子段长/方向**（实测恒等于 `[0]`）      | 段长 0 → 所有带子被跳过，一条条带都不渲染           |
| S2   | `BeltMaterial.customProgramCacheKey` 与 `CargoMaterial` 不同          | Three.js 复用错 program，箭头/位移逻辑错乱          |
| S3   | 货物矩阵必须在 `trans` 被 `multiply(scale)` 前 `copy`                 | 货物被拉长 `len` 倍、滑动量变 `len²`                |
| S4   | 不修改 `inserterTrans` / `INSERTER_HEIGHT`                            | 拾取盒与渲染错位                                    |
| S5   | `beltMesh` 可能为 `null`（全部孤立段或没有带子），帧循环与 `dispose` 判空 | 空引用崩溃                                        |
| S6   | 条带 mesh 与圆点 mesh 的实例索引互不相干，`count` 各自独立            | 圆点/条带错位或越界                                 |
| S7   | 几何释放依赖 `AllBuildings.traverse`；**材质仍不会释放（现状如此，本次不改公共 `dispose`）** | 每次重建泄漏一份材质；若强行释放需排除 `userData.sharedResource` 的 GLB 材质 |
| S8   | `CARGO_COLOR` / `BELT_ARROW_COLOR` 用 `Color` 实例常量，不在循环内 `new Color` | 每实例分配临时对象，GC 压力                        |
| S9   | 条带 `instanceColor` 必需写（G5 要求元数据色）；不要给条带材质设 `color` | 元数据色被材质色二次相乘，颜色偏暗                  |
| S10  | 圆点几何的 `translate(0,0,0.05)` 与 `rotateX(π/2)` 必须保持现有顺序    | 圆点半埋或立起来                                    |
| S11  | `bend` / `slope` 只在「输出是带子 **且** 正好一格」时非零；侧口(0.2)/隔格(2.4)/非带子一律给 0 | 分流器侧口会画出假转角、假坡度 |
| S12  | 坡度必须过 `BELT_SLOPE_EPS` 阈值                                         | ±0.01/0.02 亚台阶让整片带子出现约 1° 的可疑倾斜      |
| S13  | 条带几何长度必须烘成 `BELT_LEN`，**不能**再用实例 `scale(1,1,BELT_LEN)` | 圆弧被压成椭圆、端点错位 0.24                       |
| S14  | 货物弯折要先存 `lx/lz` 再用一元一次式写回，不能边写边读 `transformed.x`  | 第二次读到的已是被改写的值，立方体被剪切变形        |
| S15  | 转角弧长只有 78.6%，验收判据是「相位连续 + 不反向 + 无断裂」，不是「图案等长」 | 按「等长」验收会误判为缺陷                     |

## 10. 评审结论

### 10.1 结论

**建议实施（按 v3 基线）**。理由：

1. **技术栈可行**：完全复用现有「实例化 + 每实例颜色 + `onBeforeCompile`」范式，不引入新依赖、不改蓝图数据、不动拾取几何；转角与坡度只多加一个 instanced attribute，Draw Call 仍为 1。
2. **流程已修正**：v1 的几何来源（`tr[0]`→`tr[1]`）已被实测证伪并替换为「每格 + yaw + 格长常量」，同时消除了跨格相位跳变与球面堆积问题。
3. **转弯/坡度已给出唯一解**：转角圆心只能取本格中心、`R = BELT_LEN/2`（否则端点对不上邻格，§3.6）；坡度只能按「后缘取本格、前缘取邻格」并抬 `slope/2`，两者都在顶点着色器里完成。
4. **风险集中**：唯一有编译风险的环节是 `BeltMaterial` / `CargoMaterial` 的 GLSL 注入，P2/P8/P9 单独验证，且已明确 14 条实现约束（§6.5 GL1~GL14）。
5. **可回滚 / 原子性继承**：纯代码改动，`git revert` 即可；`buildBuildings` 的「先构建后替换」保证失败时保留旧场景。

**带子 → 输出格的距离直方图**（单位：格，1 格 = 1.2578 世界单位）：

```
starting_base: 1.00×301, 1.12×2, 0.93×5, 0.92×5, 0.91×2, 0.89×1, 0.88×8, 0.87×3, 0.20×6, no-output×15

sample_outpost: 0.87×4, 0.91×2, 0.20×1, 2.15×1
```

结论：

1. 绝大多数相邻带子是 1 格间距，证明「每格一段、段长 = 一格」成立；
2. 0.20 与 2.15/2.47 说明输出可能指向分流器侧口或隔格目标，**因此段长/方向不能依赖输出格位置**（这也是 P1-4「用自身 yaw 定向」的依据）；
3. `no-output` 共 25 条，必须有圆点分支（P0-3）。

**yaw → 格子方向映射**（由「自身格 → 输出格」位移反推）：

```
yaw 0   → (0, +1)     yaw 90  → (+1, 0)
yaw 180 → (0, -1)     yaw 270 → (-1, 0)
```

**与此映射一致的实现**：`base × Rx(π/2)`。`base`（`calcBuildingTrans` 的 `Ry(lon)·Rx(-lat)·Rz(-yaw)`）**已经包含 yaw**，其局部 +y 就是 `(sin yaw, cos yaw)`；`Rx(π/2)` 再把「建筑局部 +y＝流向」映射到「条带局部 -z」。

> ⚠️ 早期版本写成 `base × Rz(-yaw) × Rx(π/2)`，等于把 yaw 乘了两次（`-2·yaw`）。用 4 个 fixture 比对「本格 → 输出格」位移方向：按该写法 yaw=90/180/270 的带子同向率为 **0%**；去掉 `Rz` 后为 328/333、312/350、69/71、8/8（余下的是分流器侧口与非 90° 整数 yaw）。
