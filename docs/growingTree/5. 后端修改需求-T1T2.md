# 后端修改需求：预览事件的两处字段调整（areas 结构 / index 语义）

> 提出方：预览渲染（前端）｜对象：蓝图生成侧的 `preview-delta` 事件输出
> 结论先行：两处都是**字段形状/语义**的调整，不改事件流结构、不改数量与顺序规则。改完后前端零适配，外部端与 MES 端接同一条流也不必再各写一遍转换。

## 背景

前端接过程预览时，要拿每条 `preview-delta` 里的建筑直接把模型摆到场景里。目前有两处字段和前端既有数据结构对不上，处理起来要么得写一层"静默转换"，要么只能靠事件上的其他字段反推对象状态——这两种做法都有隐蔽的出错方式，所以希望在后端把格式/语义定清楚。

## 变更一：`areas` 里的区域描述改成嵌套结构

**现状**：事件里的 `areas` 数组，每个元素是扁平字段——`anchorLocalOffsetX`、`anchorLocalOffsetY`、`width`、`height`。

**期望**：改成与蓝图 Area 定义一致的嵌套写法——`anchorLocalOffset: { x, y }` 和 `size: { x, y }`；其余字段（`index`、`parentIndex`、`tropicAnchor`、`areaSegments`）保持原样不动。

```
现状：{"index":0,"parentIndex":-1,"tropicAnchor":0,"areaSegments":200,
       "anchorLocalOffsetX":0,"anchorLocalOffsetY":0,"width":52,"height":32}

期望：{"index":0,"parentIndex":-1,"tropicAnchor":0,"areaSegments":200,
       "anchorLocalOffset":{"x":0,"y":0},"size":{"x":52,"y":32}}
```

**原因**：前端做坐标换算时直接读 `anchorLocalOffset.x`、`size.y` 这类路径。喂扁平字段进去拿到的是 `undefined`，**不会抛错**，只会把整片区域算到原点附近——属于"不报错的错位"，现场最难排查。

**影响面**：只有 `blueprint-area-local-v1` 阶段的 `preview-delta` 带这个数组（实测每条 area-local 事件都带，且只带 1 个 area）；`layout-grid-v1` 阶段不带，不受影响。

**兼容建议**：过渡期同时输出新旧两套字段（扁平 + 嵌套），前端先只读嵌套；确认所有消费方切换后，下个版本删掉扁平字段。

## 变更二：给建筑加一个"是否临时对象"的显式标记

**现状**：`building.index` 现在有两种含义——`layout-grid-v1` 阶段恒为 `-1`；切到 `blueprint-area-local-v1` 阶段后，变成最终蓝图里的真实下标（实测 `0` 到 `N-1`，连续且唯一）。

**期望**：新增布尔字段 `isTemporary`：layout 阶段为 `true`，area-local 阶段为 `false`。`index` 现有含义保持不变（临时对象仍为 `-1`，最终对象仍是真实下标）。

**原因**：一个字段两种语义，前端既不能拿它当对象身份（临时对象全是 `-1`，会互相覆盖），也不能拿它判断"这批数据能不能用来构建正式场景"。目前只能靠事件级的 `coordinateSystem` 去反推，但有两个隐患：一是同一条事件里可能既有要删除的旧临时对象、又有新增的最终对象，事件级标记推不出单个对象的归属；二是将来若支持多区域或混合输出，事件级标记会直接失效。

**兼容建议**：纯新增字段，`index` 行为不变，因此不破坏任何现有消费方；前端在字段缺失期间按 `coordinateSystem` 兜底，字段上线后切换。命名建议 `isTemporary`（如需换名，请统一保持 camelCase）。

## 不在本次范围

- 不改 `operations` 数组结构、不改每事件 128 条上限、不改 `sequence` 规则；
- 不改 `localOffset` / `localOffset2` / `yaw` 等几何字段的命名与单位；
- 不改 `tilt` / `tilt2` / `pitch` / `pitch2`（实测一直为 0，前端按 0 处理即可）；
- 不要求补发 `preview-complete`（另议）。

## 验收口径

1. **变更一**：任取一条 `blueprint-area-local-v1` 的 `preview-delta`，`areas[0]` 里能读到 `anchorLocalOffset.x`、`anchorLocalOffset.y`、`size.x`、`size.y` 四个数值字段，且 `index` / `parentIndex` / `tropicAnchor` / `areaSegments` 与改动前一致。
2. **变更二**：任取一条 `preview-delta`，其 `add` / `replace` 操作的 `building` 都带 `isTemporary`；layout 阶段恒为 `true` 且 `index` 为 `-1`，area-local 阶段恒为 `false` 且 `index` 落在 `0..N-1`。`remove` 操作不带 `building`，无需该字段。

## 回归建议

改动只落在两条输出分支上，跑三条 delta 即可覆盖：①layout 阶段的普通一条；②坐标系切换点那条（带 `areas`）；③area-local 阶段的普通一条。三条都满足上面的验收点即完成。
