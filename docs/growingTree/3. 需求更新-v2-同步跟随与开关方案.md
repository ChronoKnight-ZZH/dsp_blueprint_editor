## 3. 执行模型 v2：同步摄入 + 每帧跟随

### 3.1 时序预算（对 50ms 的分解）

| 阶段 | 时机 | 预算 | 说明 |
| --- | --- | --- | --- |
| 摄入（ingest） | `onProgress` 回调内**同步** | ≤ 2ms / 事件 | 仅内存：`sequence` 过滤 → 逐 op 改 Map → 槽分配/标脏。**不碰 GPU、不渲染** |
| 呈现（present） | 下一个 rAF | ≤ 16.7ms（一帧） | 把脏槽写进 `instanceMatrix`/`aOpacity`，推进收敛插值 |
| 首像素可见 | 摄入后 1 帧内 | **≤ 20ms** | 满足 ≤50ms，剩余 30ms 是抖动余量 |

速率核算：250 条 / 5s = **50 条/s ≈ 每 16.7ms 0.83 条**。峰值单事件 128 op ⇒ 摄入 128 次 Map 写 + 最多 128 次槽分配，微秒级。**真正的风险不是摄入，而是首帧的槽容量分配与 GLB 首次加载**（§3.5）。

### 3.2 视觉模型：指数收敛，取代 T + LUT + 双副本

每个槽只存"当前值"和"目标值"，每帧：

```
alpha  = 1 - exp(-dt / τ)        // τ ≈ 100ms（80~150 可调）
cur   += (target - cur) * alpha   // 位置/朝向（朝向取最短角差）
opacity += (targetOpacity - opacity) * alpha
```

- **任意事件频率都稳定**：20ms 一条的事件自然合成为连续运动，不会积压；
- **移动不需要双副本**：位置插值天然就是"滑过去"，省掉一半槽位（峰值 490 对象 → 490 槽，而非 980）；
- **缓动曲线**：若坚持要正弦手感，`α` 每帧查一张按 `t/T` 的 LUT 即可，但**不再有全局 T 概念**；
- **收敛时间**：约 3τ ≈ 300ms 到稳态；事件停止后画面自动"停住"。

> 与旧方案的取舍：**"单步可看清"这一项在 v2 里消失了**（20ms/条，物理上无法单独呈现）。换来的是"全程连续、延迟 ≤20ms、不堆积"。这是你第 2 条更新的直接推论，请在验收标准里同步改口径（§6 Q1）。

### 3.3 "堆积则排队"在 v2 里落到哪里（三处，都不是播放队列）

1. **单帧摄入积压**：一次 rAF 内到达多个事件 → 全部同步摄入（顺序不乱），但**呈现**只做一次（合并中间态）。指南允许跳过中间视觉过渡；
2. **呈现超预算**：单帧写入量超过 ≈6ms → 剩余脏槽留到下一帧（**这就是"队列"的正确定位**：待刷新集合，不是时间轴）；
3. **槽容量不足**：新增对象超过预分配容量 → 本帧跳过该对象（不渲染），下一帧扩容后补齐。宁可晚一帧，也不要在事件回调里分配 GPU 缓冲。

### 3.4 commit / discard：指南语义下的收尾

- **commit**：`generateFactory` 成功返回 `result.blueprint` ⇒ `discardPreview()` + `loadBlueprint(str)`。**这是整场景替换，不是"预览层转正"**，所以 v1 里"队列播完再硬切"的焦虑不存在了：预览层是独立临时层，删掉即可；正式层由现有全量路径生成。
- **discard**：`abort` / 失败 ⇒ 立刻销毁预览层，保留上一次成功结果（指南 §2 表格一致）。
- **坐标系切换**：`layout-grid-v1` → `blueprint-area-local-v1` 是**语义跳变不是运动**，必须**硬切重投影**（不插值），否则全场会"蠕动"。指南要求"先按当前事件更新坐标解释，再应用这批变化"——即同一帧内：换投影器 → 全量重算 target → 立即写 current（跳过 alpha）。

### 3.5 抖动抑制（实测发现的真问题，已定为可配项）

7 份样本统计（`data/4.` 体检）：最大样本 `add 34,151 / remove 26,361`（**77% 的 add 最终被撤**），最初那份是 `3,179 / 2,933`（92%）。也就是说"试放-撤销"是常态，不是个别现象。

若每条 add 立刻淡入、remove 立刻淡出，画面会是**持续闪烁的噪声**，与你想要的"丝滑"相反。建议两条视觉策略（逻辑仍即时应用，不违反 50ms）：

1. **淡入 debounce**：新对象先不显示，存活 > ~120ms（且仍未被 remove）才开始淡入。代价：观感上"晚 120ms 出现"，收益：消除大部分闪现；
2. **短命对象干脆不出场**：若某对象存活时间 < ~120ms，直接不分配可见槽（只记逻辑状态）。

> 这两条做成**可配项（默认开）**：`previewThrashFilter?: { enterDelayMs: number, minLifeMs: number }`，现场可关掉做"忠实回放"对比。代码量 +10 行。

### 3.6 预览层独立（改写 v1 文档 §5.1 的结论）

v1 建议"在 `AllBuildings` 上预分配 headroom"。**在指南的约束下应改为独立预览层**，理由四条：

| 理由 | 依据 |
| --- | --- |
| 预览对象 `index = -1`，无法对上现有 BVH/选择盒/图标下标体系 | 指南 §4.1、§4 L131 |
| 预览集与正式集不同（峰值 490 vs 最终 246），生命周期只有一次生成 | 样例统计 |
| 坐标系不同，预览期要合成锚点（§3.7），与正式层的 `areas` 来源不同 | 指南 §7 |
| commit 是整场景替换，预览层必然被销毁 | 指南 §6 |

实现要点（**已按 `data/4. 多份源文件体检报告与契约问题清单.md` 修正**：峰值实测 32,581 对象，不是 490）：

- 按 `modelIndex` 分组建 `InstancedMesh`，**按需动态扩容**（模型 35 占 91%，实测 29,679 个；其余每类 ≤2 千）；保守上限按"总量 6 万 / 单模型 4 万"留 headroom；
- 用 `mesh.count = 有效数` 隐藏尾部实例（three 允许把 `count` 调到 ≤ 构造容量）；
- **禁止整块 `needsUpdate`**：3 万槽 × 64B = 2.09 MB/帧（≈125 MB/s），必须 `attribute.addUpdateRange(start, count)` + `clearUpdateRanges()` 只传脏段；
- 槽状态用 SoA 类型化数组（`Float32Array`）存，别为 3 万对象建 JS 对象；
- 材质用**克隆**（`material.clone()`）→ 顺带解决 v1 §5.2 的"污染共享材质"风险。

### 3.7 摆位：`layout-grid-v1` 怎么落到球面（**已按 7 份样本修正，见 §3.7.1**）

**好消息：不需要新写投影数学，也不需要 `findPosForAreas`。** 直接合成一个 `PositionedBlueprint` 喂给现有 `calcBuildingTrans`：

```ts
// 预览期锚点：赤道 · 本初子午线；格宽与行星最细网格 1:1
const LAYOUT_ANCHOR = {
    segment: PLANET_SEGMENT,                    // 200
    areas: [{ longitude: 0, latitude: 0, segment: PLANET_SEGMENT }],
} satisfies PositionedBlueprint;

// building 侧只需要 localOffset[2] 与 yaw[2] 这两个数组形状
const trans = calcBuildingTrans(PLANET_RADIUS, LAYOUT_ANCHOR, adapt(building));
```

依据（`src/blueprint/planet.ts:calcBuildingTrans` 与 `src/planetConstants.ts`）：格宽 = `2π/200/5 ≈ 0.36°`，与行星 LOD 网格同规格；`z` 走 `HEIGHT_GRID_SIZE`（4/3），出现时就"立在地面上"。

#### 3.7.1 单一样本会骗人：坐标跨度最大 320 格 ≈ 115°，固定赤道锚点会穿极点

| 文件 | layout 期 x | layout 期 y | 折算角度 |
| --- | --- | --- | --- |
| `044a`（最初那份） | -5 ~ 54 | -1 ~ 48 | 21° × 18° |
| `d952` | -5 ~ 106 | 0 ~ 127 | 40° × 46° |
| `27e7` | -1 ~ 110 | **0 ~ 320** | 40° × **115°** |

`y > 250` 格即超过 90°，物件会翻过极点、贴到球背面并在极点挤压。指南 §7 也写明 layout-grid "**不直接当作行星上的世界坐标**"。三选一（需你定，见 `data/4.` §7）：

| 选项 | 做法 | 代价 |
| --- | --- | --- |
| A. 球面自适应（**预留**，后续优化） | 锚点固定、**按流式 bbox 居中 + 自适应缩放**把跨度压到 ≤90°，bbox 增长超阈值（≥500ms 或 >20%）才重投影 | 偶发一次整体缩放/位移跳变 |
| B. layout 期平面俯视（**已选**） | 独立平面层呈现，area-local 切换时硬切到球面 | 与"球面工厂"观感有割裂，但零畸变、永远装得下 |
| C. 原样固定锚点 + 相机拉远 | 不改代码 | 大布局穿极点、物件重叠，**不可用** |

> **已选 B，并预留 A**：把"格坐标 → 世界矩阵"抽成一个投影器接口（`layoutProjector: (grid, z) => Matrix4`），先实现 `PlaneProjector`；将来换成 `SphereProjector` 只替换这一个实现，预览层与调度层不动。

**坐标系切换（`blueprint-area-local-v1`）**：实测每条 area-local 事件都带 `areas`（恒 1 个，area 0，`areaSegments=200`），且 40,181 次操作的坐标 **100% 落在 area 尺寸内**。此时用事件里的 `areas` 走真实 `findPosForAreas → calcBuildingTrans`，并**硬切重投影**（§3.4），不插值——实测切换点本身就是"清场 + 重建"（先 384 条 remove，再 227 条 add），不存在平滑过渡的可能。

> ⚠️ 类型陷阱：事件里的 `areas` 是**扁平字段**（`anchorLocalOffsetX/Y`、`width/height`），本仓库 `BlueprintArea` 是**嵌套字段**（`anchorLocalOffset{x,y}`、`size{x,y}`）。必须有一层适配，否则 `findPosForAreas` 拿到 `undefined` 会**静默算错位置**。`data/4.` §4.1 的 T1 已把这条列为"建议后端改"。

## 5. 开关方案（你的第 3 条，由我定）

### 5.1 三级开关（推荐）

| 层级 | 名称 | 位置 | 作用 | 默认 |
| --- | --- | --- | --- | --- |
| L1 业务级 | `emitPreviewDeltas` | **宿主页面**（不在本仓库） | 是否要过程预览：关掉则后端不产生、不发数据，**零成本** | 开 |
| L2 渲染级 | `previewAnimation: 'auto' \| 'on' \| 'off'` | **本仓库库 API**（运行时） | 事件照收，动效是否插值；`off` = 直接跳变 | `auto` |
| L3 构建级 | `DSP_ANIM=off` | 构建脚本（`vue.config.js` + `scripts/lib-build/build.js`） | 动画层代码**不进产物**（包体敏感发行） | `on` |

**为什么主控放 L2 而不是构建期**：一份产物要同时服务外部端与 MES 端，构建期只能"一刀切且要重新出包"；而 L2 走既有 `ViewerRenderSettings` + `SettingsPort`（`src/lib/types.ts:69`），宿主已经有读写通道，零新增机制。构建期那刀只用于"彻底不想让这份代码存在"的发行场景。

### 5.2 落地形态（与现有设置完全同构）

```ts
// src/renderSettingsTypes.ts 追加（纯类型，不引 vue）
export type PreviewAnimationMode = 'auto' | 'on' | 'off';
export interface ViewerRenderSettings {
    readonly showRealModels: boolean;
    readonly texturesEnabled: boolean;
    readonly maxInstancesPerModel: number;
    readonly previewAnimation: PreviewAnimationMode;   // 新增
}
```

- 宿主侧：`new BlueprintViewer({ initialSettings: { previewAnimation: 'off' } })`，或运行期 `viewer.setRenderSettings({ previewAnimation: 'off' })`；
- `auto` 判定（不引入 benchmark）：`prefers-reduced-motion` 为真 → off；`navigator.hardwareConcurrency < 4` → off；其余 on。**不做"自测帧率自动降档"**——那会与 50ms 延迟要求打架，且结果不稳定；
- 编辑器 demo：沿用 `sessionStorage`（`renderSettings.ts:158`）+ 设置面板加一个下拉；
- 诊断：`window.__DSP_PREVIEW__ = { mode, fps, pendingOps }` 只读快照，便于外部端/MES 现场排查（不需要开发者工具改代码）。

### 5.3 谁改哪个开关

| 角色 | 该用哪级 | 理由 |
| --- | --- | --- |
| 外部端（Wails 桌面） | **L2**（写自己的设置项） | 用户级偏好，可持久化到 Go 侧配置；不需要重新出包 |
| MES 用户端 | **L1 主 + L2 兜底** | 受管环境：管理员决定"是否显示生成过程"（L1，省带宽/省后端）；个别低配终端用 L2 关动效 |
| 我们的构建/发版 | L3 仅按需 | 只有"某发行版完全不带动画"时才用 |
